# Artifact Storage

Proof artifacts are optional screenshots, recordings, and diagrams generated by
agent validation. When storage is configured, Hetchy mints signed upload URLs
and the agent can attach proof links to pull request markdown.

## Local Filesystem

The Docker Compose self-host path enables local filesystem storage by default:

```dotenv
HETCHY_ARTIFACT_DIR=/data/hetchy/artifacts
```

Compose mounts a named volume at that path. Hetchy signs short-lived PUT and GET
URLs, stores uploaded files under `HETCHY_ARTIFACT_DIR`, and serves the signed
GET URLs from the web process. Set `HETCHY_PUBLIC_BASE_URL` to the externally
reachable origin before using proof links outside localhost.

To disable proof artifact uploads entirely:

```dotenv
HETCHY_ARTIFACT_DIR=
HETCHY_S3_BUCKET=
HETCHY_S3_REGION=
```

Hetchy will still run agents. Validation prompts ask the agent to report
incomplete proof artifacts instead of uploading files.

## AWS S3

S3 remains available for deployments that prefer object storage. Clear
`HETCHY_ARTIFACT_DIR`, create an S3 bucket, and set:

```dotenv
HETCHY_ARTIFACT_DIR=
HETCHY_S3_BUCKET=your-bucket-name
HETCHY_S3_REGION=us-east-1
AWS_ACCESS_KEY_ID=...
AWS_SECRET_ACCESS_KEY=...
AWS_SESSION_TOKEN=
```

The AWS identity needs permission to presign `PutObject` and `GetObject` for the
bucket prefix Hetchy writes into.

## Current Boundary

Custom S3-compatible endpoints, such as MinIO, are not wired through process
config yet. Use local filesystem storage for simple self-hosting, or AWS S3 for
object storage.
